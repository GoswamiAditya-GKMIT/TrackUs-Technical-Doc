    System Architecture

    TrackUs follows a modern, asynchronous microservices-ready architecture built on FastAPI. It emphasizes real-time capabilities and strict tenant isolation.

    Request Flow

    REST API

    Client
    → Load Balancer / Nginx → Uvicorn (ASGI Server)
    → FastAPI Router
    → Dependencies (Auth & Permissions)
    → Service Layer (Business Logic)
    → SQLAlchemy (Async ORM)
    → PostgreSQL Database

    Real-Time WebSockets

    Client
    → WebSocket Handshake
    → Connection Manager (app/realtime/manager.py)
    → Redis Pub/Sub (Message Broker)
    → Broadcaster (Fan-out to connected clients)

    Architectural Principles

    • API-First Design: All functionalities are exposed via RESTful endpoints.
    • Real-Time First: Core features like Chat and Location are built on WebSockets for sub-200ms latency.
    • Separation of Concerns: Logic is decoupled into Routers, Services, and Schemas (Pydantic).
    • Multi-Tenancy: Data is logically isolated by tenant_id at the database level.
    • Soft Deletion: Entities (Groups, Events) are marked as deleted to preserve history.

    Deep Dive: Tech Stack & Components

    1. Core Framework

    • FastAPI: High-performance Python framework for building APIs.
    • SQLAlchemy (Async): Modern ORM for asynchronous database interactions.
    • Pydantic 2.0: Data validation and serialization.
    • PostgreSQL: Primary relational database with asyncpg driver.

    2. Real-Time & Asynchronous

    • WebSockets: Native FastAPI support for bidirectional communication.
    • Redis: In-memory data store acting as:
      • Pub/Sub Broker: Distributes chat messages and location updates across server instances.
      • Celery Broker: Queues background tasks.
      • Rate Limiting Backend: Prevents API abuse.
    • Celery: Distributed task queue for non-blocking operations.
      • Tasks: Sending emails (users.tasks), data cleanup (cleanup.tasks).
    • Celery Beat: Scheduler for periodic maintenance jobs.
      • Jobs: archive_old_events, prune_inactive_users.

    3. Email Service

    • SMTP Relay: Transactional emails sent via aiosmtplib.
      • Supports providers like Brevo (Sendinblue), SendGrid, or AWS SES via standard SMTP configuration.

    Modules Breakdown

    Module Description Key Components
    auth Identity & Access Management. JWT issuance, Refresh Tokens, Blacklisting.
    tenants Organization Management. Tenant model, onboarding flows.
    users User Profiles. User model, profile application.
    groups Team Management. Group (Team) management, membership logic.
    events Trip Management. TravelEvent (Trip) creation, itinerary planning.
    chat Communication. ChatMessage, EventMessage. WebSocket endpoints.
    location Live Tracking. Real-time coordinate processing, location history.
    notifications Alerts. In-app notifications via WebSocket.

    Key Design Patterns

    Service Layer Pattern

    Business logic is abstracted away from API routes into independent Service classes (e.g., GroupService, ChatService). This ensures: - Reusability: Logic can be called from API, Celery tasks, or WebSockets. - Testability: Services can be unit tested in isolation.

    Dependency Injection

    Authentication and permissions are injected into routes using FastAPI's Depends. - get_current_user: Validates JWT. - require_tenant_admin: Enforces RBAC. - get_db: Provides a scoped database session.
