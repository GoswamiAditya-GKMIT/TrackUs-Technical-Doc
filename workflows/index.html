    Workflows & Edge Cases

    This document outlines the core business logic flows and specific edge cases handled by TrackUs.

    1. User Management Workflow

    Hierarchy & Onboarding

    1. Agency Setup: Super Admin creates a Tenant (Organization) and a Tenant Admin.
    2. User Onboarding: Tenant Admin creates Users (Travelers/Guides).
      • Constraint: Users are strictly bound to a single Tenant.

    Account Lifecycle

    • Verification: New users are created as is_active=False. They must verify via email token to login.
    • Soft Deletion: Deleting a user does not remove them from the DB.
      • Cascade Effects:
        • Removed from all Teams (Groups).
        • Status set to LEFT in all future/active Trips (Events).
        • Live Location tracking disabled.
        • Auth tokens invalidated (forced logout).
    • Hard Deletion: A nightly Celery task (cleanup.tasks) permanently wipes users soft-deleted > 30 days ago.

    2. Group Management

    Creation & Ownership

    • Any user can create a Group. The creator automatically becomes the First Admin.
    • Edge Case: The Last Admin
      • Rule: A Group MUST always have at least one Admin.
      • Constraint: The last remaining Admin cannot leave the group or demote themselves. They must promote another member first or delete the group entirely.

    Membership & Chat

    • Adding Members: Only Admins can add members.
      • Effect: Added user gets access to Group Chat history immediately.
    • Removing Members:
      • Database: left_at timestamp is set.
      • Real-Time: If the user is online in the Chat, their WebSocket connection is forcefully severed (1008 Policy Violation).

    3. Trip (Event) Lifecycle

    Trips follow a strict state machine to ensure data consistency.

    State Transitions

    From To Trigger Notes
    PLANNED ONGOING Admin Action Trip start. Live Location becomes active.
    PLANNED CANCELLED Admin Action Trip cancelled. Participants notified.
    ONGOING COMPLETED Admin Action Trip end. Location tracking stops.
    ONGOING CANCELLED Admin Action Emergency stop.
    • Edge Case: You cannot revert a COMPLETED or CANCELLED event to PLANNED.
    • Edge Case: Live Location updates are rejected if the event is not ONGOING.

    4. Participation Cycle

    Flow

    1. Auto-Invite: When a Trip is created, all Team members are automatically INVITED.
      • Creator: Automatically ACCEPTED.
    2. Response: Members must explicitly ACCEPT or REJECT.
    3. Participation: Only ACCEPTED participants can share location and view the Event Chat.

    Constraints

    • Creator Lock: The Trip creator cannot leave the Trip. They must cancel the event or delete it.

    5. Real-Time Connectivity & Reliability

    WebSocket Disconnection

    • Network Implementation: Uses Redis Pub/Sub to sync state across server instances.
    • Flow:
      1. User connects -> Authenticated via JWT.
      2. User removed from Team/Trip (via API).
      3. Server publishes "Disconnect" signal to Redis.
      4. All server instances check their active sockets and close the connection for that User ID.

    Live Location Edge Cases

    • Ghosting: If a user loses internet, their location remains "stale". The frontend shows the "Last Updated" timestamp.
    • Permission Revocation: If a user's role changes from ACCEPTED to LEFT mid-trip, their location stream is immediately cut off.

    6. Organization Deactivation

    If a Super Admin deactivates an Organization (is_active=False): 1. Login Block: No user from that Tenant can log in. 2. API Block: All active sessions are effectively killed (token validation checks user.is_active and tenant.is_active). 3. Background Tasks: Scheduled emails or notifications for that Tenant are skipped.
