    TrackUs - Technical Documentation

    Problem Statement

    The group travel industry faces significant operational challenges. Travel agencies, tour operators, and large organizations struggle to coordinate multiple groups simultaneously. Current workflows rely on a fragmented mix of WhatsApp for communication, Google Maps for location, and static PDF itineraries. This leads to communication breakdowns, safety risks (due to lack of real-time visibility), and operational inefficiency, preventing agencies from scaling their services effectively.Existing solutions often compromise on data privacy, real-time coordination, and auditability, making them unsuitable for professional or organized travel management.

    Proposed Solution

    TrackUs is a centralized Group Travel Coordination Platform designed to streamline operations and enhance traveler safety.

    • For Organization: A single dashboard to manage hundreds of client groups, ensuring data privacy and operational control.
    • For Travelers: A seamless mobile experience for real-time itinerary updates, group chat, and safety tracking.
    • Business Value: reduces manual coordination time by 40%, improves incident response time with live tracking, and increases client retention through a premium branded experience.

    TrackUs addresses these challenges with a multi-tenant, API-first backend.

    • It enforces strict data isolation using Tenant IDs across all entities (Users, Groups, Events).
    • It implements a 3-tier role system (Super Admin, Tenant Admin, User) to ensure granular access control for platform owners, agency managers, and travelers.
    • It provides real-time capabilities via WebSockets for live location tracking, instant group chat, and critical notifications.
    • It integrates background processing with Celery and Redis to handle asynchronous tasks like email notifications and data cleanup efficiently.

    Project Overview

    TrackUs is a multi-tenant travel coordination platform where data is strictly isolated by Tenant.

    Core Tenets

    • A User belongs to exactly one Tenant.
    • A Group (travel party) belongs to exactly one Tenant.
    • Cross-tenant access is strictly blocked. Users cannot view or modify itineraries or location data from other tenants.

    User Roles

    1. SUPER_ADMIN: Platform owner. Manages Tenants and Tenant Admins. Has system-wide oversight but does not participate in specific travel events.
    2. TENANT_ADMIN: Organization manager (e.g., Travel Agency Admin). Manages Users and Groups within their specific Tenant.
    3. USER: Standard traveler or member. Manages their own profile, joins groups, and participates in travel events.
    4. Group Admin: Admin of groups in an tenant.
    5. Group Member: Member of groups in an tenant.

    Key Capabilities

    • Multi-Tenancy: Complete data isolation per organization/tenant.
    • Role-Based Access Control (RBAC): Distinct permissions for platform admins, tenant managers, and end-users.
    • Real-Time Communication: WebSocket-based architecture for instant group chat and notifications.
    • Location Tracking: Secure real-time location sharing within travel groups to enhance member safety.
    • Event Management: Comprehensive scheduling for travel itineraries with participant management.
    • Scalable Architecture: Built on FastAPI and AsyncPG for high-performance asynchronous operations.

    Key Features & Enhancements

    1. Multi-Tenancy Architecture

    • Tenant-First Approach: Every user, group, and event is scoped to a specific Tenant ID.
    • Data Isolation:service-level checks ensure queries never leak data across tenant boundaries.
    • Tenant Management: Super Admins create and manage tenants, while Tenant Admins operate independently within them.

    2. Advanced Permission System

    • Super Admin: System maintenance, tenant creation, and platform-wide configuration.
    • Tenant Admin: Management of their tenant's users, creating travel groups, and overseeing events.
    • User: Varying levels of access to groups (Admin vs Member) and events (Accepted vs Invited).

    3. Real-Time Systems

    • WebSocket Manager: A robust connection manager handling user presence and message broadcasting.
    • Redis Pub/Sub: Scalable message distribution across server instances for chat and notifications.
    • Live Updates: Immediate feedback for location updates, new messages, and event status changes.

    4. Travel & Event Management

    • Group Coordination: Users are organized into Groups, allowing for persistent teams of travelers.
    • Itinerary Planning: Detailed event creation with start/end times, destinations, and auto-invitations for group members.
    • Participant State: Tracking of user responses (Accepted, Declined) and attendance status.
    • Soft Deletion: All major entities (Users, Groups, Events) support soft deletion to preserve history and prevent accidental data loss.

    Objectives

    Goal Description
    Multi-Tenancy Secure isolation of data across different travel agencies or organizations.
    RBAC Distinct roles (Super Admin, Tenant Admin, User) with specific privilege sets.
    Real-Time Low-latency communication and updates using WebSockets.
    Data Privacy Secure location sharing only within authorized groups.
    Scalability Async architecture designed to handle concurrent users and connections.
    Security JWT authentication, secure password hashing, and token usage validation.
